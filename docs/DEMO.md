# Three-minute demo

## Preparation

Start the application from the repository directory:

```powershell
python -m uvicorn server:app --reload
```

Open the localhost address printed by Uvicorn. For an offline walkthrough, leave Bifrost and Tavily credentials unset. If presenting Fix, configure `LEDGER_ALLOWED_ROOTS` to include only a disposable demo repository; do not approve a final write against a working checkout.

## Run of show

| Time | Demo |
|---|---|
| 00:00-00:30 | Open the live run screen. Point out the service status and the Brief, Fix, Red-team, and Benchmark tabs. Explain that offline operation does not imply live provider verification. |
| 00:30-01:15 | Open Brief, enter a company, and start a run. Show the timeline as events arrive and point out the evidence checks on a claim. |
| 01:15-01:45 | Open a source from its footnote or verification chip. Show its URL, date, excerpt, highlighted quote, and check results. For an offline replay source, show its local preview rather than expecting an external article link. |
| 01:45-02:15 | Open Red-team and run the scenarios. Show the reported pass or fail state and the evidence events; emphasize that results are generated by the scenario run, not prewritten UI status. |
| 02:15-02:40 | Open Benchmark. If a generated summary exists, show the arm comparison and confidence intervals. Otherwise, show the empty state and explain that the chart appears after benchmark records are summarized. |
| 02:40-03:00 | Open Fix and show the repository/task controls. Explain that test execution and applying a final diff each require their own approval, and that edits are prepared in a sandbox first. Do not approve a write unless the target is disposable. |

## Optional follow-up

For a Fix walkthrough, use a disposable copy of `bench/tasks/toy_cart`, configure its parent in `LEDGER_ALLOWED_ROOTS`, and set `LEDGER_OFFLINE_STUB=1`. Review the approval drawer before proceeding. The stub is for the seeded toy task only; it is not evidence that a live model integration works.
